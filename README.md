# SOS Safety System (Flutter)

An academic B.Tech IT project that combines the ten Flutter lab experiments in one app: an SOS safety **prototype** with emergency contacts, a cancellable SOS countdown, optional location, safety tips from a REST API, and Firebase sign-in and storage.

> **This is a prototype, not an emergency service.**
> - It never sends an SMS, places a call or contacts emergency services by itself.
> - **Demo mode is on by default.** In demo mode an alert is only recorded in your own SOS history.
> - In live mode the app can only *open* the phone dialer or message app. You still press call or send yourself.
> - Use clearly fake numbers (for example `+10000000001`) while developing.

## Features

| Area | What it does |
|---|---|
| Accounts | Email/password sign-up, sign-in and password reset (Firebase Authentication) |
| Contacts | Add, edit, delete and choose one primary emergency contact (Cloud Firestore) |
| SOS | Cancellable countdown, then a recorded alert; optional location; demo / live mode |
| Location | Reads the device location only after a button press or when you switch it on for an alert |
| Safety tips | Loaded from a REST endpoint with loading, empty, error and retry states; category filter and favourites |
| History | Append-only list of SOS events in your own account |
| Settings | Profile, countdown length, emergency number shortcut, theme, clear data, sign out |
| Notifications | Optional: registers the device for Firebase Cloud Messaging. Nothing is sent from the app (see `docs/FCM_DESIGN.md`) |

## Tech stack

Flutter and Dart, Material 3, Provider, Firebase Core / Auth / Firestore / Messaging, geolocator, url_launcher, shared_preferences, http, intl.

Verified toolchain for this project: Flutter 3.47.7 (stable), Dart 3.13.5, Firebase **Spark (free)** plan. Targets: Android (primary) and Flutter Web (demos).

## Prerequisites

- Flutter 3.47.7 stable (`flutter --version`)
- A Firebase project on the free Spark plan
- Node.js (only to install the Firebase CLI)
- Chrome (for web) and/or an Android emulator or device

## Setup

```powershell
git clone <your-repo-url> sos_safety_system
cd sos_safety_system
flutter pub get
```

Then connect your own Firebase project by following **`docs/FIREBASE_SETUP.md`**. This creates `lib/firebase_options.dart` and `android/app/google-services.json`, which are specific to your project and are not part of the source.

## Run

Start the mock tips server in one terminal (from the project root):

```powershell
dart run tool/mock_api/server.dart 8787
```

Run the app in a second terminal:

```powershell
# Web
flutter run -d chrome --dart-define=TIPS_API_URL=http://localhost:8787/tips.json

# Android emulator (the emulator reaches your PC at 10.0.2.2)
flutter run --dart-define=TIPS_API_URL=http://10.0.2.2:8787/tips.json
```

If you omit the port argument the server uses 8080 and the app's default URL matches it. On Windows, port 8080 is sometimes blocked (error 10013), so using another port such as 8787 and passing it with `--dart-define` is the reliable route. Details: `docs/API.md`.

## Test and analyse

```powershell
flutter analyze
flutter test
dart run tool/dart_basics.dart
```

Tests use in-memory fakes (`test/helpers/fakes.dart`), so they need no Firebase account or network.

## Troubleshooting (Windows)

| Problem | Fix |
|---|---|
| `npm.ps1 cannot be loaded` (execution policy) | Use `npm.cmd` instead of `npm` |
| `flutterfire` not recognised | `dart pub global run flutterfire_cli:flutterfire configure` |
| `Flutter failed to delete a directory at "build\..."` | Close running apps and VS Code, `taskkill /F /IM dart.exe`, delete `build`. Keep the project outside OneDrive (for example `C:\dev`) |
| Port 8080 error `errno = 10013` | Start the server on another port and pass `TIPS_API_URL` |
